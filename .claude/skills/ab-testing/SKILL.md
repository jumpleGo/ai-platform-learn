# A/B-тесты

## Протокол до запуска

Тест нужен для двух разумных вариантов без очевидного ответа; баги и явные UX-дефекты чинить сразу.
Одновременно не больше двух A/B. Новый тест: текущий контроль A и один фиксированный кандидат B с одним отличием.
До добавления в `EXPERIMENTS` и первой экспозиции заполнить [шаблон pre-registration](preregistration-template.md).
Сохранить в задаче версию, время UTC, гипотезу, точные тексты/макеты и commit A/B, популяцию и исключения.
Зафиксировать одну первичную метрику: события, фильтры, персональные числитель/знаменатель, окно от первой экспозиции t0.
Набор `[start UTC, end UTC)` — максимум **4 недели**; дата анализа — после созревания последнего окна измерения.
Назначение — person, анализ — уникальный `person_id`; повторы не увеличивают N. Проверить соответствие cookie `vid` и person,
заранее задать обработку слияний identity, переходов между руками, внутренних/QA/bot-событий и потери телеметрии.
Закрепить MDE, N/мощность, winner rule, метод CI, guardrails и stop rule. Вторичные метрики не заменяют первичную.
Пропуски — `NA` с причиной, ненадёжные оценки — `UNRELIABLE` с причиной; отсутствующие данные не считать нулём.
После запуска протокол менять нельзя; изменения до запуска и нарушения фиксировать в [protocol change log](preregistration-template.md#protocol-change-log).

## N sufficiency gate

До запуска считать только объём и плановый N, без исходов по вариантам, эффекта, p-value или победителя.
`p0` — baseline той же метрики за последние 28 дней до запуска: те же фильтры, персональный знаменатель и зрелые окна.
Для исторической когорты задать сопоставимый якорь вместо экспозиции; нет наблюдаемого baseline — `p0 = NA`.
Две руки 1:1, двухсторонняя α=0.05, power=0.8; MDE — минимальный полезный абсолютный эффект в долях.

```text
delta = MDE; p1 = p0 + delta; pbar = (p0 + p1)/2
n_required(delta) = ceil((1.959963985*sqrt(2*pbar*(1-pbar)) + 0.841621234*sqrt(p0*(1-p0)+p1*(1-p1)))^2 / delta^2)
```

`n_required` — на руку; коэффициенты — нормальные квантили для заданных α и power. Проверить `0 < delta <= 1-p0`.
При `p0=0/1` или малых ожидаемых числах успехов/неуспехов аппроксимация ненадёжна: до запуска нужен точный расчёт N/мощности.
Формула даёт мощность обнаружения различия при MDE; мощность полного winner rule с бизнес-порогом и guardrails обосновать отдельно.
Взять `u` из PostHog **на момент gate**: новых допустимых уникальных person/неделю, не события, сессии или повторных посетителей.
Записать источник, окно UTC, фильтры и допущение постоянного потока; прогноз набора `expected_users_4w = 4*u`.
**Если `2*n_required(MDE) > expected_users_4w`, тест не разрешён.** Неизвестный baseline, неподтверждённые поток или мощность также блокируют запуск.

> TEST NOT ALLOWED: do a targeted edit on facts and record it in the task

Пример без расчёта исходов: `4*u` участников за 4 недели — `2*u` на руку; при `n_required(MDE) > 2*u` gate не пройден.
Если полный winner rule требует большего N, проверить и его достижимость за 4 недели; меньший срок набора требует своего прогноза.
`minExposuresPerVariant` не заменяет расчёт N уникальных людей. Целевую правку по фактам записать и проверить, не выдавая за результат A/B.

## Winner rule и достижимость

Для «больше — лучше» рекомендовать B только после полного планового N в обеих руках и созревания окон,
если эффект B−A ≥ MDE, нижняя граница заранее выбранного 95% CI для B−A > 0 и guardrails соблюдены.
Метод CI задать до запуска, например Newcombe на основе Wilson; на границах он должен оставаться определённым.
P(лучше контроля) и p-value — дополнение к протоколу. Не продлевать и не останавливать тест ради значимости.
До фиксированного анализа контролировать численность и заранее заданные аварийные условия; остановку включать в отчёт.
До запуска проверить правило на синтетических крайних исходах с достаточным N, без производственных исходов:

| Доли успехов A/B | Ожидаемый вывод |
| --- | --- |
| A=B | Победителя нет; «различие не обнаружено» / inconclusive достижимо |
| A=0, B=0 | Эффект 0, победителя нет; CI определён и не ложный [0,0] |
| A=1, B=1 | Эффект 0, победителя нет; CI определён и не ложный [0,0] |
| A=0, B=1 | B может выиграть при достаточном N, допустимом MDE и соблюдённых guardrails |
| A=1, B=0 | B не выигрывает, остаётся контроль |

Не требовать обязательного победителя; недостижимый критерий или неопределённый CI исправить до запуска либо не запускать.

## Инфраструктура и работа с тестом

- `src/lib/experiments.ts`: `EXPERIMENTS`, первый вариант — контроль; `status`, `winner`, `decisionNote` хранят решение.
- `src/lib/experiments-client.ts`: `useExperiment(key, active)`; `active` — элемент показан, тогда уходит `experiment_exposed` и `$feature/<key>`.
- Жребий детерминирован по `vid` из `src/proxy.ts`; при `variant === null` спорную часть не рисовать, менять только одно отличие.
- События брать из `EVENTS` в `src/lib/analytics/events.ts`; определения `retention_w1` и L1→L2 — в шаблоне.
- Проверить A/B через `?exp_<key>=<variant>` на 390px и десктопе; QA исключить из анализа. UTM во внутренних ссылках запрещены.
- Сводка: `node scripts/ab-report.mjs [key]`; его порог и вероятность не заменяют зарегистрированные N, CI и winner rule.
- Пользователю: гипотеза, метрика, достаточность N, срок, эффект/CI, guardrails и варианты решения; решение за пользователем.
- После решения: `status: 'done'`, `decisionNote`, `winner` только при победителе; без него `pickVariant` отдаёт контроль.
- Историю в реестре сохранить; код проигравшего варианта убирать отдельным коммитом после выбора победителя.

## Negative report

Отрицательный, остановленный и недобравший N тест публиковать в той же задаче с той же видимостью, что победу.
Заполнить [шаблон отчёта](preregistration-template.md#negative-report): плановые/фактические окна и N A/B, зрелые знаменатели,
успехи, исключения, эффект B−A в п.п. и **95% CI**, метод, MDE, guardrails, нарушения протокола и решение пользователя.
Широкий CI — inconclusive; «no difference» означает «различие не обнаружено», а не доказанное равенство.
Указать, какие эффекты CI исключает и допускает. Недобор N не даёт победителя; один p-value недостаточен.
Нет знаменателя/вычислимого CI — `NA` с причиной; нарушение протокола или зависимая от исходов остановка — `UNRELIABLE` с ограничениями CI.
Нельзя скрывать остановленные тесты, публиковать только победы или задним числом объявлять анализ предварительно зарегистрированным.
