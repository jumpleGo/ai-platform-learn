# #562 — события мобильной ленты

Гипотеза: просмотр, досмотр и переход к курсу покажут, какие ролики удерживают
учеников и ведут их в уроки. Проверка на проде остаётся после выкатки; в этой
задаче выполнена локальная проверка контракта.

Объём текущего прогона: только объявления событий, подключения и тесты.
Playwright вынесен в отдельную задачу и в эту ветку не устанавливается.
Номер отдельной задачи будет указан в итогах тика; в инструкции #562 он
не передан. Сценарий 390 px со скроллом, действием «Поделиться» и трассировкой
при сбое относится к той отдельной задаче. `next build` не запускался по
прямому запрету инструкции прогона.

## Контракт

Все пять имён объявлены в `src/lib/analytics/events.ts` рядом с `lessonViewed`:
`reel_view`, `reel_complete`, `reel_like`, `reel_share`, `reel_cta_click`.
Общий тип `ReelEventProps`: `reel_id: string`, `course_slug: string | null`,
`position: number`. Позиция — индекс в массиве ленты, начиная с 0, а не поле
`order` из БД. Пустой `courseSlug` передаётся как `null`.

Повторная локальная проверка исходного кода от `40cbf806` подтвердила отсутствие
`reel_*` в `src/`. `SCHEMA_COMPAT=yes`: старые имена и свойства событий
сохранены, новая схема добавлена отдельно.

- `reel_view`: эффект активного ролика в `reels-mobile-feed.tsx`. Повторные
  записи IntersectionObserver не создают дубли. Возврат после другого ролика
  считается новым показом; повторный запуск эффекта с тем же ID — одним.
- `reel_complete`: `onEnded` и обнаружение перехода времени с последней части
  ролика к началу. У видео сохранён `loop`, который не вызывает `ended`.
  Для обнаружения петли предыдущий кадр времени должен быть в последних 10%
  длительности. Событие отправляется при возврате времени, не на отметке 90%.
  Неактивный ролик и события времени с `seeking=true` пропускаются; повторные
  петли одного показа не создают новые досмотры. При смене активности защита
  сбрасывается.
- `reel_share`: клик существующей кнопки в `reel-actions.tsx`.
- `reel_cta_click`: `onClick` существующего Link в `reel-cta.tsx`.
- `reel_like`: только объявление. Подключение вызова выполняет #560;
  существующая кнопка остаётся заглушкой.

## Проверка и объяснение теста

`tests/reel-events-562.test.tsx` проверяет имена и точные типы свойств,
нажатия share/CTA через реальные дочерние компоненты плеера (включая `null`
для курса), повторные сигналы observer, возврат к ролику, досмотр и петли.
Его объём нужен для маленького стенда хуков без новых зависимостей: стенд
сохраняет refs/state, сравнивает зависимости эффектов и прикрепляет refs до
эффектов. Обработчики и эффект ленты выполняются из рабочего кода; тест
не читает файлы исходников, `origin/main` или Git.

Тот же тест, до правки реализации, скопирован в отдельный detached worktree
от `40cbf8067da6bfb525ef41f363db21aa1a415281` с зависимостями из `npm ci`.
Результат: `OLD_FAILS=8`, один тест заглушки лайка прошёл. Worktree после
проверки удалён обычной командой без force; исходные логи, JSON-отчёт и хеш
теста сохранены в исключённом из Git каталоге `eval/` этой рабочей копии.

Изменение `reel-player.tsx` превышает 2000 символов diff: оно передаёт единый
payload кнопкам и добавляет защиту от повторных досмотров с обработкой
петель. Порядок и зависимости эффектов воспроизведения, в том числе ручная
пауза из #571, сохраняются. Diff `reels-mobile-feed.tsx` также превышает 2000
символов: отдельный эффект и ref привязывают событие к активному ID, защищая
от повторных observer-сигналов; индекс передаётся в плеер для общего payload.
Новая заметка фиксирует контракт, границы и воспроизводимую проверку; её
объём объясняется этими сведениями.

Сьюты `reel-page-556.test.tsx` и `reels-public.test.tsx`, импортирующие sitemap,
уже содержат мок `@/lib/db/reels` с реальной реализацией запроса. Чужие тесты
не изменялись: `SHARED_TEST_FILES=none`.

Команды проверки:

```sh
npx tsc --noEmit -p .
npx vitest run reel reels tests/reel-events-562.test.tsx
```

Результаты текущего кода записываются в `eval/tsc.log`, `eval/reel-tests.log`
и `eval/new-events.json`. Итог: `TSC_EXIT=0`, 12 сьютов / 219 тестов прошли,
в том числе все 9 тестов нового контракта; `OLD_FAILS=8`, `NEW_FAILS=0`.
