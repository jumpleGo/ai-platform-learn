## Исправление

- Публичная `/reels` больше не вызывает сессию. Личный результат загружается
  клиентом через GET `/api/reels/[id]/like`, использующий существующий
  `getSession`. Ответ приватный, `Cache-Control: private, no-store`.
- Admin SDK читает документ опубликованного ролика и
  `reels/{id}/likes/{sha256(uid)}` в одной транзакции. Гостю возвращаются
  только счётчик и отсутствие личного лайка; GET ничего не записывает.
- Общий `ReelLikesProvider` передаёт подтверждённые состояние и счётчик
  мобильному плееру и новой кнопке под видео компьютерного каталога.
  Переключение ширины не создаёт второй запрос и не возвращает старый счётчик.
- Во время первоначальной загрузки, POST и сверки после ошибки кнопка
  недоступна. Синхронный Set блокирует повторное нажатие даже до перерисовки.
  Состояние и счётчик меняются вместе только из ответа сервера. Результат
  другого ролика не подменяет текущий, результаты размонтированного provider
  игнорируются.
- После ошибки POST выполняется GET: потерянный ответ мог прийти после
  успешной транзакции. Повторять toggle автоматически нельзя. Если GET тоже
  не удался, остаются последние подтверждённые значения и кнопка повторного
  чтения. Некорректный успешный JSON также требует сверки.
- `reel_like` отправляется только после успешного POST с `liked: true`.
  Снятие, ошибка, сверка GET и приглашение гостю войти событие не отправляют.
  Свойства #562 сохранены точно: `reel_id`, `course_slug` (строка либо null),
  `position` (индекс ленты, не order). Share/CTA/view/complete сохранены.
- Удалён обход ошибки `useState` с пустыми setters. Используются настоящие
  хуки и клиентское состояние. Ограничитель 20 POST/минуту/ученика перенесён
  без изменения алгоритма в отдельный модуль: route.ts экспортирует только
  разрешённые Next обработчики и runtime. Правила входа, доступов и Firestore,
  запрещённые файлы и скрипты метрик не изменены.

Перед правками прочитаны установленные руководства Next по route handlers,
server/client components и Vitest из `node_modules/next/dist/docs/`.

## Почему изменены существующие тесты

1. `tests/reels-fields-555.test.ts`: семь полных ожидаемых объектов в трёх
   тестах дополнены `likeCount: 0`. `toEqual` сохранён: лишние приватные поля,
   подмена ID, CTA, текст и нормализация по-прежнему проверяются целиком.
2. `tests/reels-data.test.ts`: только ожидаемый объект `getReel` дополнен
   `likeCount: 0`. Фильтры публикации, принадлежность файлов и защита от
   приватных полей сохранены. Это адаптация к публичному контракту счётчика.
3. `tests/reel-like-560.test.ts` уже существовал в исходной ветке #560.
   Импорт сброса ограничителя перенесён из route в служебный модуль.
   Поверхностная проверка наличия route заменена сохранением через POST и
   последующим GET для того же/другого ученика, включая приватный cache header.
   Добавлено чтение гостевого счётчика без создания реакции. Существующие
   проверки 401, 404, переключения повторным запросом, изоляции учеников,
   SHA256, лимита 20/21 и SSR-разметки сохранены.
4. `tests/reel-events-562.test.tsx`: искусственный HookHarness и прямые вызовы
   функций компонентов заменены React DOM rendering и user-event. Share и
   CTA нажимаются в смонтированном плеере, view проверяется через observer
   реальных DOM-секций, ended/timeupdate — DOM-событиями видео. Проверки
   повторов, возвращения, неактивного ролика, seeking и циклов сохранены.
   Лайк теперь ждёт подтверждения API; оба значения course_slug проверяются
   отдельными случаями. Для пустого slug ожидается DOM-href `/courses`:
   настоящий Next Link нормализует исходный `/courses/`. Код CTA не менялся.
   Проверка точного единственного события одновременно исключает событие
   до нажатия; схема имён и типов #562 сохранена.
5. `tests/reels-public.test.tsx` не изменён. Все проверки публичного просмотра,
   отсутствия сессии, sitemap и гостевых ограничений сохранены и проходят.
